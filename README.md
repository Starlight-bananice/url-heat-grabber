# 链接热度抓取

本地批量链接检查与互动数据采集工具。当前正式版为 **v0.6.1**，支持实时结果、任务记录和断点续跑。macOS 与 Windows 安装包统一在同一个 Release 中发布。

本版补齐新版贴吧首帖互动栏的转发、评论、点赞、收藏；先等待帖子正文，仅在未取得正文时重新加载一次。仍然显示真实验证页时保留“需验证”。旧版不完整的贴吧进度会重新检查，其他平台的成功进度保留。Windows 另调整了控件间距，便于在较小窗口查看结果。

## 打开新版

下载对应平台的 ZIP 并解压：Mac 双击 `链接热度抓取.app`，Windows 双击 `链接热度抓取.exe`。包内包含 Python、Tk、Selenium 和 Excel 读写依赖，使用者无需另行安装这些依赖。Windows 为便携版，无需运行安装向导；自行构建时，产物位于 `dist/`。

首次抓取需要联网准备浏览器组件；平台本身的登录、验证码和访问限制仍然有效。Mac 安装包没有完成 Apple Developer ID 公证，跨电脑首次打开仍需遵循系统的安全提示。

Mac 若提示 Apple 无法验证应用，在确认下载来源和校验值后，先点“完成”，再到“系统设置 → 隐私与安全性”中找到此应用，点“仍要打开”，按提示完成授权。参见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。

## 日常使用

1. **添加链接**：粘贴链接、分享文案，或导入 TXT、CSV、XLSX。导入会追加到输入区。Excel 读取当前工作表所有列中的网址、超链接和 HYPERLINK 公式中的网址。每条提取到的完整网址按原顺序保留，重复链接也各占一行。
2. **确认设置**：默认抓取链接状态及互动数据；可改为仅检查链接。保存文件夹可更改，“更多”中可调整处理速度。完全相同的网址只抓取一次，再将结果填回每个原始位置。
3. **开始抓取**：每条结果实时出现在表格中，进度显示真实数量和比例。抓取时输入和设置会锁定，防止修改当前任务。
4. **查看结果**：“需要关注”筛选显示异常链接；“暂无互动数据”以普通状态显示，不计入关注数量。搜索可匹配链接、平台或处理结果。单击一行查看说明，双击打开网页；多选后可复制链接。“展开结果”可隐藏输入区以容纳更多结果。
5. **打开 / 导出**：成功保存后可以直接打开 Excel。抓取途中也可“另存为”导出当前快照；未处理的链接会明确标注。

### 结果含义

| 处理结果 | 含义与建议 |
| --- | --- |
| 已获取数据 | 至少一项公开互动数据已读到；“—”表示该项未获取，0 是读到的零值 |
| 可访问 | 本次仅检查链接，没有请求互动数据 |
| 暂无互动数据 | 页面可访问，但没有读到互动数；不能据此判断失效 |
| 需验证 | 平台要求验证，需在浏览器核实 |
| 访问受限 | 平台限制了本次自动访问，建议稍后再试或手动核实 |
| 已删除 | 页面明确提示内容不存在，或内容链接跳回首页；可手动复核 |
| 处理失败 | 浏览器或网络本次失败，日志中可查看原因 |
| 不支持 | 当前解析器不支持这个网址，工具没有判断它是否有效 |
| 未处理 | 本次尚未处理到，任务记录中可继续 |

### 继续任务和更新互动数据

- “继续同一批链接的上次进度”按照**链接顺序、抓取模式、解析版本**匹配。不同任务各自保存进度，不会互相覆盖。
- 恢复的已完成数据来自上次抓取。需要最新互动数时，取消继续选项，重新抓取。
- 需验证、访问受限和处理失败会在续跑时重新尝试。
- “重试待处理链接”会把未处理、验证、受限及失败的链接放回输入区，关闭续跑。点击“开始”才会发起请求。暂无数据、已删除与不支持的链接不会自动重试。
- “停止”会等待当前浏览器操作结束后保存。运行中关闭窗口可选择保存后退出；保存失败时应用会留在窗口中，便于另存结果。

### Excel 导出

导出仅包含八列：序号、链接、链接状态、点赞、评论/回复、收藏、分享/转发、播放/阅读。保留冻结表头、筛选、交替行色和可点击的网址。

未处理链接也会导出；来源页面提供的字符串按文本保存，避免被电子表格误当作公式执行。

### 删除任务记录和结果文件

在“任务记录”中选择一条或多条记录，点击“删除记录…”。默认删除所选任务的记录、链接、进度和日志；勾选“同时删除以下 Excel 结果文件”后，也会删除列出的自动导出和本版记录的另存为文件。

删除前会显示具体文件路径，取消时不执行删除。仍被其他任务引用的结果文件会保留；文件被 Excel 占用等情况导致删除失败时，保留相应任务记录供重试。任务运行期间暂不可删除记录。

## 本地文件

v0.6 系列沿用同一数据目录，保留已有设置和任务记录：

- macOS 数据：`~/Library/Application Support/URLHeatPreview/`
- Windows 数据：`%APPDATA%\URLHeatPreview\`
- 新安装的默认结果：`~/Documents/链接热度抓取/`；已有用户继续使用之前选择的保存目录。

每次任务保存独立的链接、配置、进度、任务信息与最近日志。设置和浏览器缓存独立保存。任务链接与结果都留在本机，不包含上传功能。

## 开发和验证

```bash
python -m pip install -r requirements-build.txt
python app.py
python -m unittest discover -s tests -v
# 以下测试需要可用桌面窗口服务；使用受控页面结果，不访问互联网
python tests/desktop_integration.py
./build_macos.sh
```

Windows 在 PowerShell 中执行 `./build_windows.ps1`。手动运行 GitHub Actions 的 `Build Windows x64`，会执行功能测试、真实 Tk 桌面流程、打包程序的浏览器与 Excel 自检，然后生成 ZIP 和 SHA256。将 `release_tag` 留空，仅保存构建产物；填写标签可补传到已存在的 Release。正式发布时，先检查两个平台的安装包，再统一创建正式 Release 并设为 Latest。

| 文件 | 作用 |
| --- | --- |
| `app.py` | 新版桌面界面、任务控制、实时结果、历史与指南 |
| `ui_model.py` | 导入清洗、平台识别、状态说明、任务存储与 Excel 格式 |
| `engine.py` | 原有平台抓取器，新增结构化进度与结果回调 |
| `tests/test_desktop_model.py` | 输入、导出、任务续跑与失败场景测试 |
| `tests/desktop_integration.py` | 真实 Tk 事件循环集成测试 |
| `tests/test_tieba.py` | 贴吧指标、加载状态与断点兼容回归 |
| `tests/windows_bundle.py` | Windows EXE 运行、原生窗口关闭与截图 |
| `runtime_smoke.py` | 显式开启的打包自检，使用独立目录及本地页面样本 |
| `UX_REVIEW.md` | 使用体验审查及后续优化建议 |
| `docs/VALIDATION.md` | 版本验证范围和结果 |

Mac 构建在本机验证；Windows 构建及验证在 GitHub 的 Windows 云端环境完成。验证详情见 [docs/VALIDATION.md](docs/VALIDATION.md)。受控页面测试不等于真实平台批量抓取验收，也不能替代普通用户电脑上的首次启动验收。

## 数据与使用边界

- 真实链接、账号、密码、运行日志、进度与结果文件不应提交到仓库。
- 网络访问用于目标页面处理和浏览器组件准备；程序没有自动上传用户结果的功能。
- 本仓库当前未附带开源许可证，公开仓库不等于授予商业使用或再分发权。
